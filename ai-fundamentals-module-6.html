1. Logistic Regression

Logistic regression is a classification algorithm used to predict the probability of an event belonging to a particular class. For example, a mobile money agent in Kenya might want to predict whether a customer will default on a loan. Logistic regression outputs a probability between 0 and 1, and we set a threshold (e.g., 0.5) to classify as 'default' or 'no default'. It works by fitting a logistic (sigmoid) function to the data, which maps any real number to a probability. In practice, you can use Python's scikit-learn library: from sklearn.linear_model import LogisticRegression; model = LogisticRegression(); model.fit(X_train, y_train). The model learns coefficients for each feature. For instance, if you use features like 'income', 'loan amount', and 'age', the coefficients tell you how each feature affects the log-odds of default. A positive coefficient means higher feature value increases default probability. Logistic regression is popular because it's simple, fast, and interpretable. However, it assumes a linear relationship between features and log-odds. In Africa, it's used in credit scoring, disease diagnosis, and customer churn prediction. For example, a Nigerian fintech startup might use logistic regression to classify loan applicants as high or low risk based on their transaction history. To evaluate, use accuracy, precision, recall, and F1. Always split data into training and test sets (e.g., 80/20) to avoid overfitting. Also, scale features if needed (e.g., StandardScaler). Logistic regression is a great starting point for any classification problem.

2. K-Nearest Neighbors

K-Nearest Neighbors (KNN) is a simple, non-parametric classification algorithm. It classifies a new data point by looking at the 'k' closest labeled examples in the training set and assigning the majority class. For example, if k=3 and the three nearest neighbors are two 'fraud' and one 'not fraud', the new point is classified as 'fraud'. KNN is called a lazy learner because it doesn't build a model during training; it just stores the data. To predict, it calculates distances (usually Euclidean) between the new point and all training points. In Python, use sklearn.neighbors.KNeighborsClassifier: model = KNeighborsClassifier(n_neighbors=3); model.fit(X_train, y_train). Choosing k is crucial: small k (e.g., 1) leads to overfitting; large k smooths decision boundaries but may miss local patterns. A common rule is to try k from 1 to 20 and pick the one with best cross-validation accuracy. KNN requires feature scaling (e.g., MinMaxScaler) because distance is sensitive to scale. For instance, if one feature is 'age' (0-100) and another is 'income' (0-1,000,000), income will dominate. In Africa, KNN can be used for crop disease classification from leaf images (after extracting features) or for classifying mobile phone usage patterns. However, KNN is computationally expensive for large datasets because it must compute distances to all points at prediction time. It also struggles with high-dimensional data (curse of dimensionality). Despite these drawbacks, KNN is intuitive and often surprisingly effective for small-to-medium datasets.

3. Decision Trees

A decision tree is a flowchart-like model that splits data based on feature values to make predictions. Each internal node tests a feature, each branch represents an outcome, and each leaf node gives a class label. For example, a tree might first ask 'Is income > 50,000?' then 'Is loan amount > 20,000?' to decide loan approval. Decision trees are easy to interpret and visualize, making them popular in fields like agriculture and healthcare. In Python, use sklearn.tree.DecisionTreeClassifier: model = DecisionTreeClassifier(max_depth=3); model.fit(X_train, y_train). The algorithm chooses splits that maximize information gain (or minimize Gini impurity). However, trees can easily overfit if grown too deep. To prevent this, set hyperparameters like max_depth, min_samples_split, or min_samples_leaf. You can also use pruning. For example, a tree with max_depth=3 might be more generalizable than one with depth=10. In Africa, decision trees are used to predict crop yields based on rainfall, soil type, and fertilizer use, or to diagnose diseases from symptoms. One advantage is that they handle both numerical and categorical data without much preprocessing. But single trees are unstable: small changes in data can produce very different trees. That's why ensemble methods like Random Forests (many trees) are often better. Still, learning a single tree is a great way to understand feature importance and decision logic. Always evaluate with a test set and consider cross-validation.

4. Support Vector Machines

Support Vector Machines (SVM) are powerful classifiers that find the best boundary (hyperplane) separating classes. The goal is to maximize the margin between the closest points of each class, called support vectors. For linearly separable data, SVM finds a straight line (in 2D) or hyperplane (in higher dimensions). For non-linear data, SVM uses the 'kernel trick' to map data into a higher-dimensional space where it becomes linearly separable. Common kernels: linear, polynomial, radial basis function (RBF). In Python, use sklearn.svm.SVC: model = SVC(kernel='rbf', C=1.0, gamma='scale'); model.fit(X_train, y_train). The parameter C controls the trade-off between smooth decision boundary and classifying training points correctly. A small C makes the boundary smooth (more misclassifications allowed), while a large C aims to classify all training points correctly (risk of overfitting). Gamma defines how far the influence of a single training example reaches. SVM works well for small-to-medium datasets with clear margins, such as image classification or text categorization. In Africa, SVMs have been used for classifying malaria-infected cells from microscopy images, or for credit scoring. However, SVMs are computationally intensive for large datasets and require careful tuning of C and gamma. Also, they need feature scaling. Despite these challenges, SVMs often achieve high accuracy and are robust to overfitting if tuned properly. Start with a linear kernel for text data, and RBF for non-linear patterns.

5. Naive Bayes Classifier

Naive Bayes is a probabilistic classifier based on Bayes' theorem, assuming that features are independent given the class. Despite this 'naive' assumption, it often performs well, especially for text classification. For example, you can classify emails as spam or not spam based on word frequencies. The algorithm calculates the probability of each class given the input features and picks the class with highest probability. In Python, use sklearn.naive_bayes.GaussianNB for continuous data, MultinomialNB for word counts, or BernoulliNB for binary features. For spam detection, MultinomialNB is common: from sklearn.naive_bayes import MultinomialNB; model = MultinomialNB(); model.fit(X_train_counts, y_train). The model learns prior probabilities of each class and likelihoods of each feature given the class. It's fast, requires little training data, and works well with high-dimensional data. In Africa, Naive Bayes can be used for sentiment analysis of tweets about mobile money services, or for classifying news articles by topic. It's also used in medical diagnosis, e.g., predicting disease from symptoms. However, if features are highly correlated, the independence assumption hurts performance. Also, it can be biased toward classes with more frequent features. To improve, you can use TF-IDF instead of raw counts for text. Always evaluate with precision, recall, and F1, especially if classes are imbalanced. Naive Bayes is a great baseline model due to its simplicity and speed.

6. Evaluation Metrics: Accuracy, Precision, Recall, F1

When building classification models, you need to measure how well they perform. Accuracy is the ratio of correct predictions to total predictions. But accuracy can be misleading if classes are imbalanced. For example, if 95% of loans are repaid, a model that always predicts 'repaid' gets 95% accuracy but is useless for identifying defaulters. Precision answers: Of all predicted positive cases, how many were actually positive? Recall answers: Of all actual positive cases, how many did we catch? F1 score is the harmonic mean of precision and recall, giving a balanced measure. In Python, use sklearn.metrics: from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score. For a confusion matrix, use confusion_matrix. Suppose you have a test set of 100 loans, 10 defaults. Your model predicts 8 defaults, but only 6 are true defaults. Then: accuracy = (90 correct + 6 correct) / 100 = 96%? Wait, let's compute: True Positives=6, False Positives=2, False Negatives=4, True Negatives=88. Accuracy = (6+88)/100 = 94%. Precision = 6/(6+2)=0.75. Recall = 6/(6+4)=0.6. F1 = 2*(0.75*0.6)/(0.75+0.6)=0.667. In Africa, for a mobile money fraud detection system, high recall is crucial to catch fraud, but high precision reduces false alarms. F1 balances both. Always use a test set and consider cross-validation. Also, for imbalanced data, use precision-recall curves or ROC-AUC. Choose metrics based on business goals: in disease screening, recall is more important; in spam filtering, precision might matter more.

7. Practical Reference

Practical Reference: Choosing and Evaluating Classifiers in African Agribusiness

This lesson is a working reference for turning the six classifier families in this module into decisions your team can defend in a budget meeting. In African agribusiness, the classifier is rarely the hard part the hard part is deciding which error costs more, whether your data pipeline can survive a bad rainy season, and whether a loan officer or extension agent will actually act on the output. Use this page as a lookup table when you are scoping a pilot, writing a grant proposal, or reviewing a model a vendor has pitched to you.

Classifier Cheat Sheet for Agribusiness Problems

The table below maps the six classifiers in this module onto decisions African agribusinesses actually make. The "typical data volume" column assumes you are working with farm-level or transaction-level records, not satellite rasters.

Metrics: What to Report to a Board, Not Just a Data Scientist

In agribusiness, class imbalance is the norm. Defaulters are 515% of a loan book. Diseased plants are a minority of scanned leaves. Pest outbreaks are rare events. Accuracy will look impressive and tell you almost nothing. The table below shows a worked example using a maize disease classifier deployed across 1,000 scans.

Table 2: Confusion matrix and derived metrics maize disease classifier, 1,000 scans
Predicted: Diseased Predicted: Healthy Row total
Actual: Diseased 80 (TP) 20 (FN) 100
Actual: Healthy 60 (FP) 840 (TN) 900
Column total 140 860 1,000
  • Accuracy = (80 + 840) / 1,000 = 92% sounds excellent, but misleading.
  • Precision = 80 / 140 = 57% when the model says "diseased," it is right just over half the time. Sixty farmers would spray unnecessarily.
  • Recall = 80 / 100 = 80% the model catches four in five diseased plants. Twenty cases are missed and may spread.
  • F1 = 2 (0.57 0.80) / (0.57 + 0.80) = 0.67 a balanced but unimpressive score.

Which metric matters depends on the cost of each error. For a pesticide recommendation, a false positive costs a farmer money and chemicals. For a quarantine alert, a false negative costs a region its harvest. Report all four numbers, then argue about which one your operation can tolerate.

Safety warning do not deploy classifier outputs as sole decision-makers in credit, insurance, or input distribution.

A classifier trained on historical lending data in one region will encode historical exclusion. If women farmers were under-represented in past loan approvals, a model trained on that data will systematically reject them. Always pair model output with human review, document the training population, and test for disparate impact across gender, region, and farm size before any automated approval. In several African jurisdictions, automated credit decisions may also trigger data-protection obligations under laws such as Kenya's Data Protection Act (2019), Nigeria's NDPA (2023), and South Africa's POPIA (2013).

Practical Rules of Thumb

Start with logistic regression. If it performs within a few points of a fancier model, ship it. You can explain a coefficient to a co-operative board. You cannot explain a radial basis function kernel.

Use decision trees when the output is a rule, not a score. Extension services often need "if this, then that" guidance that can be printed on a laminated card and carried to a field. A shallow tree (depth 34) is a communication tool as much as a model.

Reserve SVMs and k-NN for perception tasks. Leaf images, produce grading from cameras, acoustic pest detection these are where these methods earn their keep. They struggle to compete with tree ensembles on tabular farm records.

Naive Bayes is your baseline for text. SMS-based advisory services, farmer query routing, and multilingual keyword classification are all reasonable fits. It is fast, needs little data, and gives you a floor to beat.

Always split by time or geography, not randomly. A random split on farm data leaks information across seasons and villages. If you train on 2022 and test on 2023, you learn whether the model survives a new rainy season. This single habit prevents more deployment failures than any hyperparameter tuning.

Quick Reference Checklist

  1. Define the costly error first. Before choosing a classifier, write down whether a false positive or false negative costs more in your operation. This determines your primary metric.
  2. Check class balance. If the minority class is under 20%, stop reporting accuracy as your headline number.
  3. Split by time or region. Never use a purely random split on agricultural data with seasonal or geographic structure.
  4. Start simple. Baseline with logistic regression or Naive Bayes before trying SVM or k-NN.
  5. Report precision, recall, and F1 together. One number alone will mislead your board or your donor.
  6. Document the training population. Record who is in the data gender, region, farm size and who is missing.
  7. Plan for human review. Any credit, insurance, or input-allocation decision needs a human in the loop.
  8. Re-test each season. A model that worked last year may fail after a drought, a new variety, or a policy change.
