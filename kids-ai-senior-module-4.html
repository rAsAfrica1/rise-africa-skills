Prompt Engineering at Scale - Building Production Prompts

🧠 Brain Opener

A prompt that works once is a trick. A prompt that works a thousand times is a system. This module is about building prompts that work at scale.

  • What is the difference between a hobby prompt and a production prompt?
  • Why do you need to document prompts?
  • How do you test a prompt before using it in real work?
🎁 Reveal a good answer

A hobby prompt is improvised. A production prompt is designed, documented, tested, and versioned. You need to document prompts so others can use them and so you can improve them. You test a prompt by running it on many examples and measuring the failure rate.

📖 Tanaka Prompt Factory

Tanaka was sixteen. He had built a small freelance business writing product descriptions for online shops. His first client had ten products. His second client had fifty. His third had three hundred.

Writing each description by hand was taking him a full day per client. He was losing money.

He wrote a prompt. "Write a product description for this item." He ran it on 300 products. The results were uneven. Some were good. Some were terrible. Some were the wrong length. Some missed the price.

Tanaka rewrote the prompt. He added structure: length, tone, what to include, what to exclude. He added examples of good output. He added examples of bad output.

He ran it again. Better. He measured: out of 300 descriptions, 240 were usable, 60 needed editing. That was 80 percent. He wanted 95.

Over two weeks, he wrote 12 versions of the prompt. He tested each one on the same 300 products. He counted how many descriptions were usable without edits. Version 12 hit 95 percent.

He wrote the final prompt into a document with notes: what each part does, why it works, what to change if the client wants a different tone.

Now he could write 300 descriptions in one hour, with 95 percent quality. He charged 40 cents per description. He was making 120 dollars an hour of effort.

Tanaka had not learned a new skill. He had built a system.

💡 The Big Idea

A production prompt is a small system

A production prompt has structure. It has a role, a task, constraints, examples, and an output format. It is documented. It is versioned. It is tested. Anyone can pick it up and run it. And most importantly, it is measured - the failure rate is known and low.

📚 Three Deep Lessons

1

The five parts of a production prompt

Role: who the AI should act as. Task: what it should do, in one clear sentence. Constraints: length, tone, what to include, what to exclude. Examples: at least one good and one bad example. Output format: exactly what shape the answer should take.

A prompt missing any of these five parts will be inconsistent. The role sets voice. The task sets purpose. The constraints set boundaries. Examples set quality. Format sets usability.

2

Why you test on many examples

A prompt that works on three examples might fail on 30. A prompt that works on 30 might fail on 300. You cannot know the failure rate until you test at the scale you will use.

The professional test is simple: pick 20 real examples. Run the prompt on all 20. Count how many outputs are usable without edits. If it is under 90 percent, keep improving. If it is over 90, you have a production prompt.

3

Version and document

Every time you improve a prompt, save the old version. Number them. Keep notes on what changed and why. In two months, you will not remember why version 7 was replaced by version 8. Your notes will.

The documentation is also what makes the prompt transferable. If a client, an employee, or a partner needs to use your prompt, they need to understand it. A well-documented prompt is a product.

🛠 Hands-On - Build a Production Prompt

You need

  • A phone or laptop with AI access
  • A document to save your prompts
  • 20 real examples of a task you do
  1. Pick a task you do at least weekly.
  2. Write a first version of the prompt with the five parts: role, task, constraints, examples, format.
  3. Run it on 20 real examples. Count how many outputs are usable without edits.
  4. If under 90 percent, revise the prompt. Test again.
  5. Keep testing until you reach 90 percent or higher.
  6. Document the final version: what each part does, why it works.
  7. Save it as your production prompt.
Why it works: A production prompt is measured. Until you know the failure rate, you do not have a production prompt. You have a hope.

🎮 Game - Prompt Battle Royale

3 to 12 players - 25 min

The teacher gives one task - write a short product description for a named item. Every player writes a prompt to do the task on 10 items. Then every prompt is run on the same 10 items. Outputs are judged blind by another group. The prompt with the highest percentage of usable outputs wins.

🏆 Project Challenge

Build a Prompt Library of 5

Build five production prompts for five real tasks.

  1. Pick five tasks you do every week.
  2. For each, write a prompt with the five parts: role, task, constraints, examples, format.
  3. Test each on 20 real examples. Count usable outputs.
  4. Revise until each hits 90 percent or higher.
  5. Write documentation for each: what it does, why it works, when to use it.
  6. Save the whole library in one document. Test it with a friend.
