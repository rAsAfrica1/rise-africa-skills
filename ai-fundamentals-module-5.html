1. Simple Linear Regression

Simple linear regression predicts a number using one input. For example, a maize farmer in Kaduna might want to predict yield (in bags per hectare) from rainfall (in mm). You collect data: rainfall and yield for 20 seasons. The model finds a line: yield = 2.5 + 0.03 * rainfall. That means for every extra mm of rain, yield increases by 0.03 bags. The 2.5 is the interceptthe yield when rainfall is zero (not realistic, but it anchors the line).

To build this, you can use Python with scikit-learn. Load your data into a pandas DataFrame. Split into X (rainfall) and y (yield). Then: from sklearn.linear_model import LinearRegression; model = LinearRegression(); model.fit(X, y). The model learns coefficients. You can predict for a new rainfall value: model.predict([[500]]) gives the expected yield.

In Africa, simple linear regression helps small businesses. A poultry farmer in Ghana can predict egg production from feed quantity. A transport company in Kenya can predict fuel cost from distance travelled. The key is having clean data: no missing values, and the relationship should look roughly linear when you plot a scatter plot.

Always check the residualsthe differences between actual and predicted values. If they show a pattern (like a curve), a straight line may not be best. You can calculate R-squared to see how much variation in yield is explained by rainfall. An R-squared of 0.75 means 75% of yield changes are explained by rainfall. The rest is due to other factors like soil quality or pests.

Start with simple linear regression because it is easy to interpret and fast to train. Even with one input, you can make actionable decisions: if rain is below 400 mm, expect low yield and plan irrigation. This is the foundation for more complex models.

2. Multiple Linear Regression

Multiple linear regression uses two or more inputs to predict a number. For a maize farmer, yield might depend on rainfall, fertilizer used (kg/ha), and temperature (C). The model: yield = b0 + b1*rainfall + b2*fertilizer + b3*temperature. Each coefficient tells you how much yield changes when that input increases by one unit, holding others constant.

In practice, you gather data on all inputs and the output. Using Python: X = df[['rainfall', 'fertilizer', 'temperature']]; y = df['yield']; model = LinearRegression().fit(X, y). Then model.coef_ gives [b1, b2, b3] and model.intercept_ gives b0. For a new farm with rainfall=600, fertilizer=100, temperature=28, you predict yield.

This is powerful for African businesses. A bakery in Lagos can predict daily bread sales from day of week, temperature, and promotions. A mobile money agent in Uganda can predict transaction volume from number of customers, location foot traffic, and hour of day. The key is to avoid multicollinearitywhen inputs are highly correlated. For example, rainfall and humidity might be correlated, making coefficients unstable. Check correlation matrix and remove one if correlation > 0.8.

Always scale your features if you use regularization later, but for plain multiple regression, scaling is not required for prediction. However, it helps compare coefficient sizes. For example, if fertilizer coefficient is 0.5 and rainfall coefficient is 0.02, fertilizer has a larger effect per unit, but units differ. Standardizing inputs (mean=0, std=1) makes coefficients comparable.

Evaluate with R-squared and adjusted R-squared. Adjusted R-squared penalizes adding useless inputs. If adding temperature only increases R-squared from 0.80 to 0.81, it may not be worth the complexity. Use statsmodels for detailed summary: import statsmodels.api as sm; model = sm.OLS(y, X).fit(); print(model.summary()). This shows p-values for each coefficient, telling you which inputs are statistically significant.

3. Polynomial Regression

Polynomial regression is used when the relationship between input and output is curved, not straight. For example, crop yield may increase with rainfall up to a point, then decrease due to flooding. A straight line would miss that. Polynomial regression adds squared and cubed terms: yield = b0 + b1*rainfall + b2*rainfall^2 + b3*rainfall^3.

In Python, you can create polynomial features using sklearn.preprocessing.PolynomialFeatures. For degree=2: from sklearn.preprocessing import PolynomialFeatures; poly = PolynomialFeatures(degree=2); X_poly = poly.fit_transform(X). Then fit LinearRegression on X_poly. The model learns coefficients for rainfall, rainfall^2, etc. You can predict for new rainfall values.

Use polynomial regression when you see a curve in your scatter plot. In Africa, this applies to fertilizer response: too little fertilizer gives low yield, optimal amount gives high yield, too much can burn plants. Also, temperature and milk production: cows produce more milk at moderate temperatures, less when too hot or too cold.

But be careful: high-degree polynomials (degree > 3) can overfitthey fit noise in your data and perform poorly on new data. Always split data into training and test sets. If training R-squared is 0.99 but test R-squared is 0.60, you overfit. Reduce degree or use regularization.

You can also use polynomial regression for time series with seasonal patterns. For example, monthly sales of a product may have a yearly cycle. Adding month squared and cubed can capture that. But often, more data or different models (like Fourier terms) work better. Start with degree 2, check test performance, then try degree 3. Plot the fitted curve against actual data to visually check.

Remember to center and scale your data before creating polynomial terms to avoid numerical instability. In scikit-learn, use Pipeline: from sklearn.pipeline import make_pipeline; model = make_pipeline(PolynomialFeatures(degree=2), LinearRegression()). This handles scaling if you add StandardScaler.

4. Regularization: Ridge and Lasso

Regularization prevents overfitting by adding a penalty to the model for large coefficients. Ridge (L2) adds penalty = alpha * sum(coefficient^2). Lasso (L1) adds penalty = alpha * sum(|coefficient|). Alpha controls strength: higher alpha means more penalty, simpler model. In scikit-learn: from sklearn.linear_model import Ridge, Lasso; model = Ridge(alpha=1.0); model.fit(X, y).

When to use Ridge vs Lasso? Ridge shrinks coefficients but keeps all inputs. Lasso can shrink some coefficients to exactly zero, effectively selecting important features. If you have many inputs and suspect only a few matter, use Lasso. For example, predicting crop yield from 20 soil nutrientsLasso might pick only nitrogen, phosphorus, and potassium. Ridge is better when all inputs contribute a little.

In Africa, regularization helps with small datasets. A startup in Nairobi with only 50 customer records and 10 features can use Ridge to avoid overfitting. The model will generalize better to new customers. You can tune alpha using cross-validation: from sklearn.linear_model import RidgeCV; model = RidgeCV(alphas=[0.1, 1.0, 10.0]); model.fit(X, y); print(model.alpha_).

Always scale your features before regularization because the penalty depends on coefficient size. Use StandardScaler: from sklearn.preprocessing import StandardScaler; scaler = StandardScaler(); X_scaled = scaler.fit_transform(X). Then fit Ridge or Lasso on X_scaled. Without scaling, a feature with large units (e.g., rainfall in mm) will have a small coefficient, so penalty affects it less, which is unfair.

Lasso can also help with interpretability: if it sets a coefficient to zero, you can drop that input. This is useful for building simple models for mobile apps or low-resource settings. For example, a farming advice app can ask only 3 questions instead of 10. Ridge is preferred when you believe all inputs are relevant but correlated. Both are available in scikit-learn and are fast to train.

5. Model Evaluation Metrics for Regression

To know if your regression model is good, you need metrics. The most common are Mean Absolute Error (MAE), Mean Squared Error (MSE), Root Mean Squared Error (RMSE), and R-squared (R). MAE is average absolute difference between actual and predicted. MSE squares differences, penalizing large errors more. RMSE is square root of MSE, in same units as target. R is proportion of variance explained, from 0 to 1 (higher better).

In Python, use sklearn.metrics: from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score. After predictions: mae = mean_absolute_error(y_test, y_pred); mse = mean_squared_error(y_test, y_pred); rmse = mse**0.5; r2 = r2_score(y_test, y_pred). Always evaluate on a test set, not training data.

For African contexts, choose metrics that matter. If predicting maize yield in bags, MAE tells you average error in bags. If MAE=2 bags, your predictions are off by 2 bags on average. RMSE is more sensitive to large errorsif one prediction is off by 10 bags, RMSE will be higher. R tells you how much better than just predicting the mean. R=0.8 means 80% of variation explained.

But R can be misleading if you add many inputs. Use adjusted R: adj_r2 = 1 - (1-r2)*(n-1)/(n-p-1), where n is samples, p is predictors. Also, always compare to a baseline: predict the mean. If your model doesn't beat that, it's useless. For example, if average yield is 20 bags, and your model's MAE is 5 bags, but predicting 20 always gives MAE of 6 bags, your model is only slightly better.

Plot residuals: residuals = y_test - y_pred. They should be randomly scattered around zero. If they show a pattern (e.g., increasing with predicted values), your model is missing something. Use matplotlib: import matplotlib.pyplot as plt; plt.scatter(y_pred, residuals); plt.axhline(0, color='red'). This visual check is as important as numbers. In low-resource settings, MAE is often easiest to explain to stakeholders.

6. Cross-Validation Techniques

Cross-validation (CV) gives a more reliable estimate of model performance than a single train-test split. The most common is k-fold CV: split data into k folds (e.g., 5). Train on k-1 folds, test on the remaining fold. Repeat k times, each fold as test once. Average the scores. In scikit-learn: from sklearn.model_selection import cross_val_score; scores = cross_val_score(model, X, y, cv=5, scoring='neg_mean_absolute_error'); print(scores.mean()).

Why use CV? With small datasets, a single split might be lucky or unlucky. For example, a Ghanaian cocoa farmer with 30 years of data: if you use 20 for training and 10 for testing, the test set might be unusually good or bad. 5-fold CV uses all data for both training and testing, giving a stable estimate. It also helps tune hyperparameters like alpha in Ridge.

For time series data, use TimeSeriesSplit. It respects temporal order: train on past, test on future. For example, predicting monthly sales: train on months 1-24, test on 25-30; then train on 1-30, test on 31-36. This mimics real forecasting. In scikit-learn: from sklearn.model_selection import TimeSeriesSplit; tscv = TimeSeriesSplit(n_splits=5).

Leave-One-Out CV (LOOCV) uses one sample as test, rest as train, repeated for all samples. It's computationally expensive but useful for very small datasets (e.g., 10 samples). For most African business datasets (50-500 rows), 5-fold or 10-fold CV is sufficient. Stratified k-fold is for classification, not regression.

Always scale inside CV to avoid data leakage. Use Pipeline: from sklearn.pipeline import make_pipeline; from sklearn.preprocessing import StandardScaler; model = make_pipeline(StandardScaler(), Ridge()). Then cross_val_score(model, X, y, cv=5). This ensures scaling is fit only on training folds. Report mean and standard deviation of scores. A high standard deviation means performance varies across foldsyour model may be unstable. In that case, collect more data or simplify the model.

<h2>Practical Reference: Regression in African Agribusiness</h2>

<p>This practical reference is the working manual for the six lessons in Supervised Learning: Regression. It is written for the African agribusiness professional who needs to move from concept to decision: forecasting maize yields, pricing fertilizer, estimating transport costs, or predicting loan repayment risk. Every technique in this module Simple Linear Regression, Multiple Linear Regression, Polynomial Regression, Ridge and Lasso Regularization, Model Evaluation Metrics, and Cross-Validation is only as valuable as the business decision it supports. Use this page as a desk reference during model building and, more importantly, during model review with your team.</p>

<h3>1. Choosing the Right Regression Technique</h3>

<p>Start with the business question, not the algorithm. If you are asking "how much does one extra kilogram of NPK fertilizer change my maize yield per hectare?", Simple Linear Regression is sufficient and explainable to a cooperative board. If you are asking "what combination of rainfall, seed variety, soil pH, and labour days best predicts yield across 12 districts?", you need Multiple Linear Regression. If the relationship is curved for example, yield rising with fertilizer up to a point and then flattening or declining Polynomial Regression captures that non-linearity. If you have many correlated predictors, such as rainfall, humidity, and evapotranspiration, Ridge and Lasso Regularization prevent the model from overfitting and, in the case of Lasso, automatically select the most useful variables.</p>

<h3>3. Interpreting Evaluation Metrics in Business Terms</h3>

<p>Metrics are not academic decorations. Each one answers a specific business question. RMSE tells you the typical size of your forecast error in the same units as your target for example, "our maize yield forecast is typically off by 0.4 tonnes per hectare." MAE is easier to explain to a board because it is a simple average of absolute errors. R tells you what share of yield variation your model explains, but it can be misleading with few observations. MAPE expresses error as a percentage, which is useful when comparing forecasts across crops of very different scales.</p>

<h3>4. Cross-Validation in Practice</h3>

<p>Cross-validation is how you estimate real-world performance before committing capital. For most African agribusiness datasets, which are small and often grouped by district or season, standard k-fold cross-validation can leak information between training and test folds. Use these rules:</p>

<ul>
<li><strong>k = 5 or 10</strong> for general use; k = 5 is safer with fewer than 200 observations.</li>
<li><strong>GroupKFold</strong> when records come from the same district, cooperative, or farm keep all records from one group in the same fold.</li>
<li><strong>TimeSeriesSplit</strong> when predicting future seasons; never train on future data to predict the past.</li>
<li><strong>Stratified folds</strong> when your target has distinct ranges (e.g. low, medium, high yield zones).</li>
<li><strong>Nested cross-validation</strong> when tuning Ridge or Lasso alpha values, to avoid optimistic bias.</li>
</ul>

<p>A practical workflow: split 70/30 into development and holdout sets. Use 5-fold GroupKFold on the development set to tune alpha and select features. Then evaluate once on the holdout set. Report both the cross-validated RMSE and the holdout RMSE. If they differ by more than 20%, your model is unstable and should not be deployed.</p>

<h3>5. Ridge vs. Lasso: A Decision Rule</h3>

<p>Use Ridge when you believe all your predictors carry some signal and you want to shrink their coefficients smoothly for example, rainfall, humidity, temperature, and soil organic matter all plausibly affect yield. Use Lasso when you suspect many predictors are irrelevant and you want the model to select a short list for example, when you have 40 surveyed variables but only 8 are likely to matter. In practice, Elastic Net (a blend) is often the safest default. Always standardise predictors before regularizing, because Ridge and Lasso penalise coefficients on the scale of the input variables.</p>

<h3>6. Quick Reference Checklist</h3>
<ol>
<li><strong>Define the business target</strong> in measurable units (kg/ha, USD/tonne, days) before touching data.</li>
<li><strong>Clean and standardise units</strong>; document every imputation and outlier decision.</li>
<li><strong>Plot the data first</strong> scatterplots reveal whether linear, multiple, or polynomial form is appropriate.</li>
<li><strong>Check for multicollinearity</strong> (correlation matrix, VIF); apply Ridge or Lasso if VIF &gt; 10.</li>
<li><strong>Split data properly</strong> group by district/farm and respect time order where relevant.</li>
<li><strong>Use cross-validation</strong> (GroupKFold or TimeSeriesSplit) to tune hyperparameters, never the holdout set.</li>
<li><strong>Report MAE, RMSE, and R together</strong>; translate each into a business sentence for stakeholders.</li>
<li><strong>Verify input ranges</strong> before every deployment; refuse to extrapolate beyond training data.</li>
<li><strong>Re-validate each season</strong> climate, input prices, and varieties change, so models decay.</li>
</ol>
