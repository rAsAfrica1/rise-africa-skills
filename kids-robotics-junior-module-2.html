1. Coordinate Frames and Transformations

In robotics, you need to describe where things are. A coordinate frame is like a local map attached to each part: the base, each arm segment, the gripper. In Africa, where many workshops use low-cost robots like the 2-DOF arm from Arduino or the KUKA youBot, understanding frames is the first step to programming movement. Imagine a solar panel cleaning robot in Ghana: its base frame is fixed to the ground, while the brush frame moves along the panel. To convert a point from the brush frame to the base frame, you use a transformation matrix. A 2D transformation has three parts: rotation (angle) and translation (x, y). For example, if the brush is 0.5 m from the base and rotated 30 degrees, the matrix is [[cos30, -sin30, 0.5], [sin30, cos30, 0], [0,0,1]]. Multiply this by a point in the brush frame to get its position in the base frame. In 3D, you add a third rotation and z translation. Free tools like Python with NumPy or MATLAB make this easy: define a 4x4 homogeneous matrix. Practice with a simple 2D arm: base at (0,0), link1 length 0.3 m at 45 degrees, link2 length 0.2 m at 90 degrees. Compute the end-effector position by multiplying frames. This is how you control a robot to weld a metal frame in a Nairobi workshop. Always label your frames clearly: base, joint1, joint2, tool. Use the right-hand rule to remember rotation directions. Without frames, you cannot command a robot to pick up a mango in a warehouse in Senegal.

2. Forward Kinematics for Serial Manipulators

Forward kinematics (FK) answers: given joint angles, where is the robot's hand? For a serial arm, you multiply transformation matrices from base to tip. Consider a 2-DOF planar arm like the one you'll simulate in L6: link1 length L1 = 0.4 m, link2 length L2 = 0.3 m, both in a plane. Joint angles Î¸1 and Î¸2 are measured from the horizontal. The end-effector position (x, y) is: x = L1*cos(Î¸1) + L2*cos(Î¸1+Î¸2), y = L1*sin(Î¸1) + L2*sin(Î¸1+Î¸2). That's it! In 3D, you use Denavit-Hartenberg (DH) parameters: four numbers per joint (a, alpha, d, theta). Many African robotics startups, like those building agricultural drones or sorting arms, use DH tables. For a 6-DOF arm, you multiply six matrices. Free software: Python with SymPy or ROS's tf library. In a typical workshop in Lagos, you might calibrate a robot to spray paint a car door. FK tells you where the spray nozzle is for given motor angles. If your calculation is off by 1 cm, the paint misses. So always verify with a ruler or a motion capture system. Practice: write a Python function that takes L1, L2, Î¸1, Î¸2 and returns x, y. Test with Î¸1=0, Î¸2=0 (should be L1+L2, 0). Then Î¸1=90, Î¸2=0 (should be 0, L1+L2). This builds intuition before inverse kinematics.

4. Jacobian and Velocity Kinematics

The Jacobian matrix relates joint velocities to end-effector velocities. For a 2-DOF planar arm, the Jacobian J is a 2x2 matrix: J = [[-L1*sin(Î¸1) - L2*sin(Î¸1+Î¸2), -L2*sin(Î¸1+Î¸2)], [L1*cos(Î¸1) + L2*cos(Î¸1+Î¸2), L2*cos(Î¸1+Î¸2)]]. Compute J: row1: -0.4*0.5 -0.3*0.966 = -0.2 -0.29 = -0.49; -0.3*0.966 = -0.29. row2: 0.4*0.866 +0.3*0.259 = 0.346+0.078=0.424; 0.3*0.259=0.078. So J = [[-0.49, -0.29], [0.424, 0.078]]. Determinant = (-0.49*0.078) - (-0.29*0.424) = -0.038 + 0.123 = 0.085. If v = [0.1, 0] m/s, then Î¸_dot = J^{-1} * v. Compute inverse: J^{-1} = (1/det) * [[0.078, 0.29], [-0.424, -0.49]] = (1/0.085)*[[0.078,0.29],[-0.424,-0.49]] = [[0.918, 3.41], [-4.99, -5.76]]. Then Î¸_dot = [0.918*0.1 + 3.41*0, -4.99*0.1 + -5.76*0] = [0.0918, -0.499] rad/s. So joint1 speeds up, joint2 reverses. This is crucial for controlling a robot's speed. When the arm is fully stretched (Î¸2=0), the Jacobian becomes singular (determinant zero), meaning some directions are impossible. In African workshops, you see this in robot arms that jam when trying to move straight out. Use the Jacobian to plan smooth trajectories. Tools: Python with NumPy, or MATLAB. For a 6-DOF arm, the Jacobian is 6x6. Singularities cause loss of control. Always check determinant or condition number.

5. Dynamics: Newton-Euler and Lagrangian Formulations

Dynamics tells you how much torque or force is needed to move a robot. Newton-Euler is a recursive method: go from base to tip to compute velocities and accelerations, then back to compute forces and torques. Lagrangian uses energy: kinetic minus potential. For a 2-DOF planar arm with point masses m1, m2 at the ends of links, the Lagrangian L = T - V. T = 0.5*m1*(L1*Î¸1_dot)^2 + 0.5*m2*[(L1*Î¸1_dot)^2 + (L2*(Î¸1_dot+Î¸2_dot))^2 + 2*L1*L2*Î¸1_dot*(Î¸1_dot+Î¸2_dot)*cos(Î¸2)]. V = m1*g*L1*sin(Î¸1) + m2*g*(L1*sin(Î¸1) + L2*sin(Î¸1+Î¸2)). For a 6-DOF arm, use Newton-Euler for efficiency. Tools: Python with SymPy, or MATLAB Robotics Toolbox. Simulate in PyBullet to verify. Dynamics is key for a robot that picks up a heavy object, like a 5 kg bag of maize in a Kenyan mill.

6. Lab: Simulating a 2-DOF Planar Arm in Python


Use this Python snippet to simulate FK, IK, and Jacobian for a 2-DOF arm. This is the same code used in our Rise Africa Robotics lab.



import numpy as np
import matplotlib.pyplot as plt

L1, L2 = 0.4, 0.3  # link lengths in meters

def fk(theta1, theta2):
    x = L1*np.cos(theta1) + L2*np.cos(theta1+theta2)
    y = L1*np.sin(theta1) + L2*np.sin(theta1+theta2)
    return x, y

def ik(x, y):
    c2 = (x**2 + y**2 - L1**2 - L2**2) / (2*L1*L2)
    c2 = np.clip(c2, -1, 1)
    theta2 = np.arccos(c2)
    theta1 = np.arctan2(y, x) - np.arctan2(L2*np.sin(theta2), L1 + L2*np.cos(theta2))
    return theta1, theta2

    J = np.array([
        [-L1*np.sin(theta1) - L2*np.sin(theta1+theta2), -L2*np.sin(theta1+theta2)],
        [ L1*np.cos(theta1) + L2*np.cos(theta1+theta2),  L2*np.cos(theta1+theta2)]
    ])
    return J
