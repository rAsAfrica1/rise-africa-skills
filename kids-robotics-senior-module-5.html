1. Introduction to Arduino and Raspberry Pi

Microcontrollers are the brains of most robots. In this lesson, you'll learn about two popular platforms: Arduino and Raspberry Pi. Arduino is a microcontroller board that runs one program repeatedly. It's great for controlling sensors, motors, and lights in real time. Raspberry Pi is a tiny computer that runs an operating system like Linux. It can do complex tasks like image processing but isn't as good at precise timing. For a line-following robot, Arduino is often the better choice because it reacts instantly to sensor inputs.

In Africa, Arduino Uno clones are widely available for about 5,000 to 10,000 Naira (or equivalent) in local electronics markets like Computer Village in Lagos or Alaba International. Raspberry Pi 4 costs around 50,000 to 80,000 Naira. Both can be powered by USB power banks or 9V batteries. You'll need a computer to program thema laptop with Windows, Mac, or Linux works. The Arduino IDE is a free download, and it includes many example programs.

To get started, connect your Arduino to your computer with a USB cable. Open the Arduino IDE, select the correct board and port, and upload the 'Blink' example. This makes the built-in LED blink every second. That simple test confirms your setup works. For Raspberry Pi, you'll need to install an operating system on a microSD card using the Raspberry Pi Imager. Then you can connect a monitor, keyboard, and mouse to use it like a desktop.

When choosing between them, consider your robot's needs. If you need to read sensors and control motors with precise timing, use Arduino. If you need to process camera images or connect to the internet, use Raspberry Pi. Many advanced robots use both: a Raspberry Pi for high-level decisions and an Arduino for low-level control. For this module, we'll focus on Arduino because it's cheaper, simpler, and perfect for a line-following robot. You can buy an Arduino Uno clone, a USB cable, and a few sensors for under 15,000 Naira total.

2. Digital and Analog I/O Programming

Digital I/O means reading or writing only two states: HIGH (5V) or LOW (0V). Analog input reads a range of voltages, usually 0 to 5V, and converts them to a number between 0 and 1023. On Arduino, digital pins are numbered 0 to 13, and analog input pins are A0 to A5. You use pinMode() to set a pin as INPUT or OUTPUT, digitalWrite() to set an output HIGH or LOW, and digitalRead() to read an input. For analog, use analogRead() on an analog pin.

A practical example: reading a push button. Connect one side of the button to 5V and the other side to pin 2, with a 10k resistor from pin 2 to ground. This is a pull-down resistor. When the button is pressed, pin 2 reads HIGH; otherwise, it reads LOW. In code, you'd set pinMode(2, INPUT) and then use digitalRead(2) to check the state. For analog, connect a potentiometer: middle pin to A0, outer pins to 5V and ground. analogRead(A0) will give 0 when turned fully left and 1023 when fully right.

Outputs: To light an LED, connect it from pin 13 to a 220 resistor to ground. digitalWrite(13, HIGH) turns it on. For analog output, Arduino doesn't have true analog output, but it can simulate it using PWM (Pulse Width Modulation) on pins 3, 5, 6, 9, 10, and 11. analogWrite(pin, value) where value is 0 to 255 sets the duty cycle. This is useful for dimming LEDs or controlling motor speed.

In a line-following robot, you'll use digital inputs to read infrared sensors (which output HIGH or LOW depending on whether they see a line) and analog inputs to read more precise sensors. You'll use digital outputs to control motor driver pins. Always use current-limiting resistors with LEDs to avoid burning them out. A typical IR sensor module costs about 500 Naira in local markets, and you can build your own with an IR LED and photodiode for even less. Practice by writing a program that reads a button and turns on an LED when pressed, then modify it to use analog input to control LED brightness.

3. Interfacing Sensors and Actuators

Sensors convert physical quantities into electrical signals. Actuators convert electrical signals into physical action. For robotics, common sensors include infrared (IR) reflectance sensors for line detection, ultrasonic sensors for distance measurement, and temperature sensors. Actuators include DC motors, servo motors, and stepper motors. In this lesson, you'll learn how to connect and program them with Arduino.

Start with an IR reflectance sensor. It has two pins: one for power (5V and GND) and one for signal. The signal is digital: LOW when it sees a black line (because black absorbs IR light) and HIGH when it sees a white surface (reflects IR). Connect the signal pin to Arduino digital pin 2. In code, use digitalRead(2) to check. A typical module costs 300-500 Naira. For better precision, use an analog IR sensor or a QTR-8A array, which gives analog readings.

Ultrasonic sensor (HC-SR04) measures distance by sending a sound pulse and timing its echo. It has four pins: VCC, GND, Trig, and Echo. Connect Trig to pin 9 and Echo to pin 10. In code, send a 10-microsecond HIGH pulse to Trig, then measure the time Echo stays HIGH using pulseIn(10, HIGH). Distance in cm = time / 58. This sensor costs about 1,500 Naira and is great for obstacle avoidance.

Actuators: DC motors need more current than Arduino can provide, so you need a motor driver like L298N or L293D. The L298N module costs around 1,000 Naira and can control two motors. Connect Arduino pins to the driver's input pins, and the motors to the output pins. For a servo motor (like SG90), connect its signal wire to an Arduino PWM pin (e.g., 9). Use the Servo library: #include , then myservo.attach(9) and myservo.write(angle). Servos are used for steering or moving arms.

When interfacing, always check voltage and current ratings. Never connect a motor directly to Arduino pinsyou'll damage the board. Use a separate power supply for motors if needed, and connect all grounds together. Practice by building a simple circuit: an IR sensor that turns on an LED when it detects a line, then replace the LED with a motor driver to spin a motor. This is the basis of your line-following robot.

4. Serial Communication: UART, I2C, SPI

Serial communication allows microcontrollers to talk to each other, to sensors, and to computers. The three main protocols are UART, I2C, and SPI. UART (Universal Asynchronous Receiver-Transmitter) uses two wires: TX (transmit) and RX (receive). It's simple and used for programming Arduino and for connecting to devices like GPS modules. On Arduino Uno, pins 0 (RX) and 1 (TX) are used for UART. You can use the Serial library: Serial.begin(9600) sets the baud rate, Serial.print() sends data, and Serial.read() receives data.

I2C (Inter-Integrated Circuit) uses two wires: SDA (data) and SCL (clock). It supports multiple devices on the same bus, each with a unique address. On Arduino Uno, SDA is A4 and SCL is A5. I2C is perfect for sensors like the MPU6050 (accelerometer and gyroscope) or OLED displays. You need the Wire library: Wire.begin(), Wire.beginTransmission(address), Wire.write(data), Wire.endTransmission(), and Wire.requestFrom(address, bytes). Typical I2C devices cost from 1,000 to 5,000 Naira.

SPI (Serial Peripheral Interface) uses four wires: MOSI (Master Out Slave In), MISO (Master In Slave Out), SCK (clock), and SS (slave select). It's faster than I2C and used for SD cards, RFID readers, and some displays. On Arduino Uno, pins 11 (MOSI), 12 (MISO), 13 (SCK), and 10 (SS) are used. You use the SPI library: SPI.begin(), SPI.transfer(data). SPI devices can be more expensive but offer high speed.

For a line-following robot, you might use I2C to connect an LCD screen for debugging, or UART to send data to a computer for monitoring. If you add a Bluetooth module (HC-05) for remote control, it uses UART. Remember to connect grounds between devices. Also, ensure logic levels match: most Arduino sensors are 5V, but some are 3.3V. Use a logic level converter if needed. Practice by connecting an I2C OLED display and printing sensor readings on it, or by sending data from Arduino to your computer's serial monitor.

5. Real-Time Operating Systems for Robotics

A Real-Time Operating System (RTOS) helps you manage multiple tasks with precise timing. In robotics, you often need to read sensors, control motors, and communicate simultaneously. Without an RTOS, you might use delay() or millis(), but that can cause missed sensor readings or jittery motor control. An RTOS like FreeRTOS allows you to create tasks that run concurrently, each with its own priority.

FreeRTOS is free and works on Arduino (especially ESP32, which has two cores). On a standard Arduino Uno, memory is limited, but you can still use a simple scheduler. For more complex robots, consider an ESP32, which costs about 3,000 Naira and has built-in WiFi and Bluetooth. With FreeRTOS, you create tasks using xTaskCreate(). Each task is a function that runs in an infinite loop. You can set priorities: higher priority tasks run first. Use vTaskDelay() to yield control to other tasks.

For a line-following robot, you might have three tasks: one reads IR sensors every 5ms, one controls motors every 10ms, and one checks for commands via Bluetooth every 100ms. The sensor task has highest priority to ensure timely line detection. Use queues to send data between tasks safely. For example, the sensor task sends sensor values to a queue, and the motor task reads from that queue. This avoids race conditions.

If you don't use an RTOS, you can implement a simple cooperative scheduler using millis(). For example, check if 5ms have passed since last sensor read, then do it. This is called a state machine. It's simpler but requires careful coding to avoid blocking. For most beginner robots, a state machine is enough. But as your robot gets more complex, an RTOS becomes valuable. Practice by writing a program that blinks two LEDs at different rates without using delay(), using millis(). Then try FreeRTOS on an ESP32 if available.

6. Lab: Building a Line-Following Robot

In this lab, you'll build a line-following robot using an Arduino Uno, two IR reflectance sensors, an L298N motor driver, two DC motors, a chassis, and a battery pack. The goal is to make the robot follow a black line on a white surface. Total cost: about 15,000 to 20,000 Naira if you source parts locally. You can use a cardboard or acrylic chassis, or buy a robot car kit for around 10,000 Naira.

First, assemble the chassis. Mount the two DC motors with wheels on either side, and a caster wheel at the front or back for balance. Attach the IR sensors at the front, facing down, about 1-2 cm above the ground. Place them close together (about 2-3 cm apart) so they can detect the line. Connect the sensors: VCC to 5V, GND to GND, and signal pins to Arduino digital pins 2 (left sensor) and 3 (right sensor). Connect the L298N: input pins to Arduino pins 4, 5, 6, 7 (or use PWM pins for speed control), and motors to the output terminals. Power the L298N with a 6-12V battery pack (e.g., 4 AA batteries or a 9V battery). Connect Arduino GND to L298N GND.

Write the code. Define pins. In setup(), set sensor pins as INPUT and motor pins as OUTPUT. In loop(), read both sensors. If both see white (HIGH), go forward. If left sees black (LOW) and right sees white, turn left. If right sees black and left sees white, turn right. If both see black, stop or go forward (depending on line width). Use digitalWrite() to control the motor driver. For example, to go forward: digitalWrite(4, HIGH); digitalWrite(5, LOW); digitalWrite(6, HIGH); digitalWrite(7, LOW). To turn left: left motor backward, right motor forward.

Test on a track made of black electrical tape on a white surface. Adjust sensor sensitivity using the potentiometers on the IR modules. If the robot oscillates, reduce speed or move sensors closer to the ground. If it loses the line, check sensor placement and code logic. Common issues: sensors not detecting due to ambient light, motors not turning due to insufficient power, or wiring errors. Use a multimeter to check voltages. Once working, you can add a buzzer or LED to indicate line detection. This lab gives you a complete robotics project you can show to employers or use as a base for more advanced robots.

7. Practical Reference


Practical Reference: Microcontrollers & Embedded Systems for African Robotics Ventures



This practical reference is written for African robotics entrepreneurs, TVET instructors, and agritech integrators who need to move from "blinking an LED" to shipping a working product. The lessons in this module cover Arduino and Raspberry Pi, digital and analog I/O, sensors and actuators, serial buses (UART, I2C, SPI), and real-time operating systems. This reference consolidates the engineering decisions that determine whether your robot prototype becomes a sellable product or a drawer of dead boards.



Across Africa, the strongest robotics demand signals are in agriculture (weeding, spraying, yield mapping), logistics (warehouse and last-mile delivery), mining safety, and healthcare delivery. Your microcontroller choice should be driven by the customer's problem, not by what is trending on GitHub. A solar-powered soil-moisture logger for a smallholder cooperative in Kenya has different constraints than a warehouse AGV in Lagos or a mine-safety drone in Johannesburg.





Choosing Your Platform: Arduino vs Raspberry Pi vs ESP32



The most common costly mistake in African robotics startups is picking a Raspberry Pi for a job that needs an Arduino, or vice versa. The Pi is a general-purpose Linux computer: excellent for vision, networking, and dashboards, but it has no hard real-time guarantees and can crash on a power dip. A microcontroller (Arduino, STM32, ESP32) runs one program deterministically, boots in milliseconds, and survives brownouts far better critical when your robot runs off a solar-charged battery in rural Kenya or a generator-backed workshop in Accra.



The practical pattern that wins in the field: a microcontroller handles the real-time control loop (motor PID, sensor sampling, safety cutoffs), and a Raspberry Pi handles high-level tasks (camera, LTE upload, operator UI). They talk over UART. This split lets you ship a working product now and upgrade the brain later without rewriting the control firmware.

Digital and Analog I/O: The Engineering Reality



Digital I/O reads or writes HIGH/LOW. Analog input uses the ADC to read a voltage. Two numbers matter in every African deployment:



  • ADC resolution: Arduino Uno = 10-bit (01023 over 05 V). ESP32 = 12-bit (04095 over 03.3 V). Raspberry Pi has no ADC you must add an external chip (e.g. MCP3008 over SPI).

  • Logic voltage: Mixing 5 V Arduino sensors with 3.3 V ESP32 or Pi GPIO will destroy pins. Use a level shifter or a voltage divider. This is the single most common hardware failure we see in student and startup labs.



For analog sensors in dusty, humid African environments (soil moisture, turbidity, gas), always calibrate in situ. A capacitive soil probe reading 2.1 V in the lab will read differently after two weeks in red Kenyan soil. Store calibration constants in EEPROM or flash so a power cycle does not lose them.

SAFETY WARNING Battery, Motor, and Mains Hazards

Robotics in African field conditions combines high-current batteries, fast-spinning motors, and unreliable mains power. Never connect a motor directly to a microcontroller GPIO the inrush current will destroy the pin and can start a fire. Always use a motor driver (L298N, TB6612, or DRV8833) with a properly rated fuse and a flyback diode. Lithium batteries (LiPo, 18650) must be charged on a balance charger in a fireproof bag, never unattended overnight, and never in a shack or vehicle. If your robot touches mains (pumps, chargers, workshop tools), use an RCD/earth-leakage breaker and keep 230 V wiring physically separated from 5 V logic. In areas with unstable grid power, add surge protection and a battery-backed UPS to protect both equipment and operators. When in doubt, de-energize and get a qualified electrician.




Interfacing Sensors and Actuators Field-Proven Practices



Sensor selection in Africa is a supply-chain decision as much as an engineering one. Prefer parts you can reorder locally or via regional distributors (e.g. RS Components South Africa, Mouser, or trusted Alibaba vendors with local returns). Avoid exotic sensors with no local stock a failed $80 sensor with a six-week lead time kills a harvest-season deployment.




  • Debounce everything mechanical. Limit switches, reed switches, and cheap buttons bounce. Software debounce (1050 ms) or an RC filter saves you from phantom triggers.

  • Filter analog sensors. Use a moving average or median filter. Dust, humidity, and long unshielded wires inject noise.

  • Drive actuators through isolation. Relays for pumps and solenoids; motor drivers for DC/stepper motors; opto-isolators where ground loops are likely.

  • Protect against brownouts. Add a watchdog timer; if the MCU hangs, it resets. Add a large bulk capacitor near the motor driver.



Real-Time Operating Systems for Robotics



Bare-metal loops are fine for a line-follower. They break down when you add Wi-Fi, logging, and multiple sensors. An RTOS (FreeRTOS, Zephyr, or ChibiOS) gives you tasks, priorities, and deterministic scheduling. On ESP32, FreeRTOS is already there use it. On a Raspberry Pi, use PREEMPT_RT or, better, offload hard timing to a microcontroller. For most African robotics startups, the winning architecture is: RTOS on the MCU for control, Linux on the Pi for intelligence.



Lab: Building a Line-Following Robot Business Notes



The line-follower lab is not just a teaching exercise; it is a miniature of every autonomous ground vehicle. The skills map directly to:



  • Agritech: row-following weeders and sprayers (replace the line with a crop row via camera or IR).

  • Warehouse: AGVs following magnetic or QR-coded paths.

  • Education market: sell line-follower kits to schools and TVET colleges a real revenue line for African robotics startups.


Build it with an Arduino Nano, two IR reflectance sensors, an L298N driver, and a 2-cell 18650 pack. Get it working on a clean floor, then test it on uneven ground, in sunlight, and on dusty concrete the conditions your customers actually have. If it survives that, you have a product.



Quick Reference Checklist



  1. Match platform to task: MCU for real-time control, Pi for vision/networking; link them over UART.

  2. Check logic voltages before wiring level-shift 5 V 3.3 V to avoid frying pins.

  3. Never drive motors or relays directly from GPIO; use a driver with fuse and flyback protection.

  4. Calibrate analog sensors in the field and store constants in EEPROM/flash.

  5. Debounce mechanical inputs and filter analog signals in software.

  6. Choose buses deliberately: I2C for short multi-sensor, SPI for speed, UART for module links.

  7. Add a watchdog timer and brownout protection for unstable power environments.

  8. Test on real African terrain dust, sun, uneven ground, intermittent power before shipping.
